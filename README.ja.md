# Fluid

[English](README.md) | [Deutsch](README.de.md) | [Français](README.fr.md) | [Italiano](README.it.md) | [Português](README.pt.md) | [العربية](README.ar.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | 日本語

あなたのコーディングエージェントが代わりにやってくれない 2 つのことを、キーボードの前にいない間に片づけます。

- **窓を開けておく** —— 前の利用枠の窓がリセットされたらすぐ新しい窓を開けます。誰も作業していなくても同じです。戻ってきたときには、満タンの枠がすでに動き出しています。
- **通知** —— それがうまくいかなくなったときに知らせます。Bark、ntfy、メール、そのほか繋ぎたいものは何でも。

利用制限で止まったセッションの続きは、今ではエージェント自身が引き受けます。それが起きなかったときは、Fluid が代わりに続けさせます（下の「再開」を参照）。

## 対応エージェント

Claude Code、Codex、Antigravity はどれも同じ形で計量します。最初のリクエストから始まる短い窓と、その上により長い周期の枠です。インストールされているものを Fluid が維持します。

| エージェント | 枠の情報の出どころ | 設定への変更 |
|--------------|--------------------|--------------|
| Claude Code | Fluid プラグインのフック・モジュール、使用量が変わるたび | なし |
| Codex | セッションログ、必要なときに読む | 変更なし |
| Antigravity | statusLine、更新のたび | statusLine 1 項目 |

エージェントごとに窓・予約・通知は別々で、互いに混ざりません。もう 1 つ増やすにはファイルを 1 つ書くだけです（[docs/PROVIDERS.md](docs/PROVIDERS.md)）。計量の仕方はインターフェースで明示されます。維持しても意味がないエージェントがあるからです。Kimi Code の短い窓は枠ではなくリクエストの速度を制限し、Grok Build は週単位の枠が 1 つあるだけで短い窓がありません。どちらも開けておく窓がありません。

## 何が嬉しいか

**窓をいつ開けたかが、いつ終わるかを決める。** 窓は固定の時刻ではなく、最初のリクエストから始まります。5 時間の窓を例にすると、9 時に仕事を始めてそのまま使えば窓は 9:00〜14:00。11 時に枠を使い切れば 14:00 まで待つしかありません。もし 6 時に小さなリクエストが窓を開けていれば、その窓は 11:00 に期限切れ —— ちょうど枠が尽きる時刻 —— で、新しい枠がすでに用意されています。窓が常に回っていれば、仕事を始めるときにはもう 1 つ動いています。その残りは本来使われずに消える枠で、次の新しい枠は長くても窓 1 つ分、たいていはもっと早く来ます。

**窓は早く開けるほど、一日により多く収まる。** 9 時に始めてそのまま使えば、窓は 9:00〜14:00 と 14:00〜19:00 の 2 つで終業を迎えます。もし 6:00 に 1 つ開いていれば、その日は 6:00〜11:00、11:00〜16:00、16:00〜21:00 の 3 つで覆われます。机に向かう時間は同じで、枠は 1 つ多いわけです。下の「決まった時刻」はそのためにあります。

**助けにならなくなった時がわかる。** 窓を開けておけるのは、ログインが有効でスケジューラが動いている間だけで、どちらかが止まれば何も起きません。Fluid はどちらも見分けて知らせます。週末じゅう黙って失敗し続けたりはしません。

## 必要なもの

Linux または macOS 上で、`jq`、そして `claude`、`codex`、`agy` のうち少なくとも 1 つ。Claude Code にはプラグインとして Fluid を入れてください（下記）。使用量の読み取りと「再開」は、プラグインのフック・モジュールが受け持ちます。Linux では実行を `at` で予約するので `atd` が動いている必要があります。macOS では launchd が引き受けるので設定は要りません。Windows では、systemd を有効にした WSL の中で Claude Code を動かしてください（atd を起動するため）。

```bash
sudo systemctl enable --now atd   # Linux
brew install jq                   # macOS
```

## インストール

```bash
npx fluid-agents
```

クローンから実行する場合：

```bash
git clone https://github.com/MrJasonZhou/fluid.git
cd fluid
bash install-fluid.sh
```

Claude Code のプラグインとして入れ、インストーラを Claude Code の中から実行することもできます。

```
/plugin install fluid --marketplace MrJasonZhou/fluid
/fluid:install
```

`/fluid:status`、`/fluid:anchor`、`/fluid:uninstall` が使えるようになり、Claude Code の中で動くフック・モジュールも入ります。このモジュールが使用量の読み取りを Fluid に渡し、止まったセッションを再開させます（「再開」参照）。Claude Code の設定には一切手を付けません。フック・モジュールはアカウントごとに順次有効化中です。モジュールが読み込まれない環境やプラグインなしの場合、Fluid には Claude Code の読み取りが届きません。最初の読み取りが届くまでは何も予約せず、その後は推定したリセット時刻だけを頼りに続けます。モジュールが読み込まれなかったときは、インストーラがそう伝えます。読み取りがどこから来ているかは `/fluid:status` で確認できます。

Antigravity については、インストーラが既存の statusLine を包み込みます（表示はこれまでとまったく同じです）。その設定への変更はこれだけで、設定ファイルはどれも先にバックアップされます。Codex と Claude Code には設定が一切要りません。再実行は二重インストールではなくクリーンな更新になり、各エージェントの次に予約された実行とその状態、そしてあなたの通知スクリプトは引き継がれます。0.3.0 より前の版は Claude Code の statusLine も包み、その設定にフックを 1 つ加えていました。プラグインを入れる前に一度アンインストール（下記）すれば、どちらも取り除かれます。

## 使い方

普段は何も実行する必要がありません —— ひとりでに働きます。様子を見たいときは：

```bash
~/.fluid/fluid.sh status    # 各エージェントの窓・予約・失敗回数
~/.fluid/fluid.sh providers # どのエージェントが入っているか
tail -f ~/.fluid/fluid.log  # 何をしてきたか
```

## 決まった時刻に開ける

既定では前の窓がリセットされ次第すぐ開くので、連鎖は最後に枠を使い切った時刻に従います。毎日の決まった時刻に固定するには：

```bash
~/.fluid/fluid.sh anchor 06:00   # 毎日 06:00 に開ける
~/.fluid/fluid.sh anchor         # 現在の設定を表示
~/.fluid/fluid.sh anchor off     # すぐ開ける動作に戻す
```

その時刻をまたいでしまう窓は、代わりにその時刻まで待ちます。03:00 に開く予定の窓は 03:00〜08:00 を覆って 06:00 を飲み込むので、06:00 に開きます。そのぶん時刻の手前の数時間は窓がありません。その時間帯に作業すれば、いつもどおりあなたの最初のリクエストが窓を開けます。この設定はすべてのエージェントに効きます。

## warm-up に使うモデル

窓をひとつ開けるにもリクエストは 1 回かかるので、Fluid はそれを各エージェントの CLI が許す範囲で最小にします。短いプロンプトを 1 つ、`/` で実行するだけです。Claude Code ではいちばん安いモデルを使い、ツールもなし、履歴にも残しません。Codex は読み取り専用で動かし、セッションのファイルを残しません。Antigravity はふだんどおりに動きます。モデルは入れ替わります。いま使っているものをエージェントが知らなくなると、その旨をはっきり返すので、Fluid はそのエージェント自身の既定のモデルに切り替えて一度だけ知らせます。誰かがログを読むまで窓ごとに失敗し続ける、ということにはなりません。

```bash
~/.fluid/fluid.sh model                 # 各エージェントが何で warm-up しているか
~/.fluid/fluid.sh model claude sonnet   # 自分で選ぶ
~/.fluid/fluid.sh model claude auto     # いちばん安いものに戻す
```

## 再開

Claude Code は利用制限がリセットされると、自分でセッションを再開します（`/config` の "Continue automatically at usage limit"）。ところが、うっかり押したキーでカウントダウンが取り消されたり、そもそも始まらなかったりして、再開されないことがあります。そうなると、気づくまでセッションは止まったままです。Fluid はその受け皿です。フック・モジュールが制限で止まったセッションを覚えておき、リセットの 3 分後にもう一度見に行きます。まだ止まっていれば、あなたと同じように `continue` を送ります。

それ以外のときは手を出しません。Claude Code かあなたがすでに続けている場合や、入力欄に書きかけがある場合は何も送りません。試すのは最大 2 回で、それでも駄目なら知らせます。プラグインと、そのフック・モジュールを読み込む Claude Code が必要です。

## 通知

Fluid は普段は黙っていて、あなたの対応が要るときだけ知らせます。伝えるのは次の 6 つだけです。

| | |
|---|---|
| **サインアウト** | あるエージェントのログインが切れており、入り直すまでそのエージェントでは何も開けない |
| **連続して失敗** | あるエージェントの warm-up が何度か続けて失敗した |
| **スケジューラ停止** | 予約した実行が大きく遅れており、窓が開けられていない。たいていは `atd` が動いていない |
| **復旧** | 上の不具合のいずれかから元に戻った |
| **warm-up のモデルが消えた** | あるエージェントの warm-up に使っていたモデルがもう存在しないので、以後はそのエージェントの既定を使う |
| **再開できなかった** | 利用制限のリセット後もセッションが止まったままで、`continue` を送っても動かなかった |

それぞれエージェントごとに一度だけ知らせ、リトライのたびには鳴りません。夜間に問題が起きても届くのは 1 通です。自然に直った失敗なら 1 通も来ません。サインアウトは、あとの再確認も失敗してから初めて知らせます。利用制限そのものは決して知らせません。あれは日常的なもので、エージェントが（駄目なら Fluid が）続きを引き受けます。

受け取り方を選ぶには、見本をひとつコピーして自分のキーやサーバーを書き入れます。

```bash
cd ~/.fluid
cp notify/bark.sh.sample notify.sh      # ntfy.sh.sample、email.sh.sample でも可
chmod +x notify.sh                      # メール版はパスワードを持つので 700 に
$EDITOR notify.sh
./fluid.sh notify-test            # 実際に届くか確かめる
```

通知スクリプトは単なる実行可能ファイルで、`CP_EVENT`、`CP_MESSAGE`、`CP_HOST` を受け取ります。Telegram でも Slack でも webhook でも `mail` でも、書き換えるのは一行です。あなたが用意したものは再インストールしても残ります。

## ファイル

すべて `~/.fluid/` の下にあります。

| | |
|---|---|
| `fluid.sh` | スクリプト本体 |
| `providers/` | エージェントごとに 1 ファイル |
| `state/<エージェント>/` | そのエージェントの窓・予約・通知の状態 |
| `notify.sh` | あなたが用意した通知スクリプト |
| `notify/` | コピー元の見本 |
| `anchor` | 設定した窓を開ける時刻（設定していれば） |
| `fluid.log` | 何をしてきたか |

## アンインストール

```bash
npx fluid-agents uninstall
```

クローンからの場合：`bash install-fluid.sh uninstall`。

各エージェントの設定をその場で編集し、Fluid が追加したものだけを取り除きます。元の statusLine は戻り、それ以外の設定はすべてそのまま残ります —— Fluid をインストールした後に追加されたものも含めて。予約されたジョブは取り消され、`~/.fluid/` は削除されます。あなたの `notify.sh` も一緒です。二度実行しても害はありません。

その後に別のプログラムがどれかの statusLine を Fluid の外側から包んでいても、アンインストールでそれを壊すことはありません。そのプログラムが動き続けるよう小さな中継スクリプトを残し、その旨を表示します。不要になったらもう一度アンインストールしてください。同じ状況での更新も、そのプログラムを包み返すのではなく、その連鎖の内側に留まります。

アンインストール直前の各設定ファイルのコピーがすぐ隣に残り、インストール時のコピーも残る（新しいものから五つまで）ので、手で戻す必要があれば使えます。
